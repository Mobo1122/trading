  1. **ScannerDeps dataclass** (dependency injection container):
     - `iv_engine: IVEngine`
     - `earnings_calendar: EarningsCalendar`
     - `redis_client: Any` (for latest market data lookup via HGET)
     - `watchlist: list[str]`
     - `settings: Settings`

  2. **scanner_agent = Agent(...)** definition:
     - `model` param: Will be set at runtime from config (use placeholder string, overridden in run_scanner)
     - `output_type=ScannerOutput`
     - `deps_type=ScannerDeps`
     - `instructions`: System prompt explaining the scanner's role:
       "You are an options trading opportunity scanner. Your job is to analyze symbols from the watchlist and identify high-probability options trading opportunities. Use the provided tools to gather IV analytics, earnings data, and current market prices. Focus on:
       1. High IV rank (>60) suggesting options are expensive -- good for selling premium
       2. Low IV rank (<30) suggesting options are cheap -- good for buying premium
       3. Symbols approaching earnings (within 7 days) for IV expansion plays
       4. Significant bid/ask spread opportunities
       Return only genuine opportunities with clear reasoning. If no opportunities exist, return an empty list -- do not invent opportunities."
     - `model_settings=ModelSettings(temperature=0.1, max_tokens=2000)`

  3. **Tools** (decorated with @scanner_agent.tool):

     **get_iv_data(ctx: RunContext[ScannerDeps], symbol: str) -> str**:
     - Calls `await ctx.deps.iv_engine.compute(symbol)` to get IVData
     - Returns JSON string of IVData model (iv_rank, iv_percentile, current_iv, etc.)
     - If IVEngine raises or returns None, return JSON with error message

     **get_earnings_info(ctx: RunContext[ScannerDeps], symbol: str) -> str**:
     - Calls `ctx.deps.earnings_calendar.get_upcoming(symbol)` to check earnings
     - Returns JSON with earnings_date, days_until, eps_estimate if available
     - If no upcoming earnings, return JSON indicating no earnings nearby

     **get_market_snapshot(ctx: RunContext[ScannerDeps], symbol: str) -> str**:
     - Reads latest quote from Redis via HGET `market_data:{symbol}` (the pattern used by RedisDistributor in Phase 2)
     - Returns JSON with bid, ask, last, volume, implied_volatility
     - If no data in Redis, return JSON indicating no recent data

     **get_watchlist(ctx: RunContext[ScannerDeps]) -> str**:
     - Returns JSON list of symbols from deps.watchlist
     - This gives the LLM the full symbol list to scan

  4. **run_scanner helper function**:
     ```python
     async def run_scanner(
         deps: ScannerDeps,
         model: str | None = None,
         usage_limits: UsageLimits | None = None,
     ) -> tuple[ScannerOutput, Usage, list]:
     ```
     - Creates the prompt: "Scan the following symbols for options trading opportunities: {deps.watchlist}. Use the tools to gather IV, earnings, and market data for each symbol. Return your analysis."
     - Runs `await scanner_agent.run(prompt, deps=deps, model=model, usage_limits=usage_limits)`
     - If no usage_limits provided, use default: `UsageLimits(request_limit=10, response_tokens_limit=4000)`
     - Returns tuple of (result.output, result.usage(), result.all_messages())
     - Log via structlog: agent name, num opportunities found, token usage

  All tool functions must handle exceptions gracefully (try/except returning error JSON, never crashing the agent run).
