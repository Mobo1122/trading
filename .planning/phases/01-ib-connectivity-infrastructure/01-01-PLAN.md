    **Configuration system (`src/trading/config.py`):**

    Implement the layered configuration using pydantic-settings with these nested models:

    - `TradingConfig`: `mode: Literal["paper", "live"] = "paper"` with a property `ib_port` that returns 4001 for live, 4002 for paper. Add a validator that defaults to "paper" if the value is not exactly "paper" or "live" (safety -- ambiguous config means paper).
    - `IBConfig`: `host: str = "127.0.0.1"`, `port: int = 4002`, `client_id: int = 1`, `timeout: float = 30.0`, `max_reconnect_attempts: int = 0` (0=infinite), `reconnect_delay: float = 5.0`, `reconnect_max_delay: float = 120.0`
    - `DatabaseConfig`: `url: str = "postgresql+asyncpg://trading:trading@localhost:5432/trading"`, `pool_size: int = 10`, `pool_overflow: int = 5`
    - `RedisConfig`: `url: str = "redis://localhost:6379/0"`, `contract_cache_ttl: int = 3600`
    - `LoggingConfig`: `level: str = "INFO"`, `format: Literal["json", "console"] = "console"`
    - `Settings(BaseSettings)`: Contains all above as nested models. Configure with `env_prefix="TRADING_"`, `env_nested_delimiter="__"`. For YAML loading, use a custom `settings_customise_sources` classmethod that loads from `config/default.yml` first, then mode-specific YAML (paper.yml or live.yml based on TRADING_MODE env var), then env vars (highest priority). Use `pyaml-env` to support `${ENV_VAR}` interpolation in YAML files. Add a `@classmethod` factory method `Settings.load()` that handles the YAML loading order.

    Important: The `ib.port` field in IBConfig is the OVERRIDE port. The `TradingConfig.ib_port` property is the DERIVED port from mode. In the connection manager (future plan), use `settings.trading.ib_port` to get the correct port. Document this clearly in a docstring.

    **YAML config files:**

    `config/default.yml`:
    ```yaml
    trading:
      mode: paper
    ib:
      host: "127.0.0.1"
      client_id: 1
      timeout: 30.0
      max_reconnect_attempts: 0
      reconnect_delay: 5.0
      reconnect_max_delay: 120.0
    database:
      url: "postgresql+asyncpg://trading:trading@localhost:5432/trading"
      pool_size: 10
      pool_overflow: 5
    redis:
      url: "redis://localhost:6379/0"
      contract_cache_ttl: 3600
    logging:
      level: "INFO"
      format: "console"
    ```

    `config/paper.yml` (paper-specific overrides):

    ```yaml
    logging:
      level: "WARNING"
    ```

    **Docker Compose (`docker-compose.yml`):**

    Define three services following the research Pattern 4 exactly:
    - `ib-gateway`: `ghcr.io/gnzsnz/ib-gateway:stable`, ports 4001/4002/5900 bound to 127.0.0.1, env vars from .env (`TWS_USERID`, `TWS_PASSWORD`, `TRADING_MODE`), `AUTO_RESTART_TIME: "11:55 PM ET"`, `TWOFA_TIMEOUT_ACTION: restart`, volume `ib-gateway-data:/root`, restart unless-stopped
    - `timescaledb`: `timescale/timescaledb:latest-pg16`, port 5432 on 127.0.0.1, env vars `POSTGRES_DB=trading`, `POSTGRES_USER=trading`, `POSTGRES_PASSWORD=${POSTGRES_PASSWORD:-trading}`, volume `timescaledb-data`, healthcheck with `pg_isready`, restart unless-stopped
    - `redis`: `redis:7-alpine`, port 6379 on 127.0.0.1, volume `redis-data`, healthcheck with `redis-cli ping`, restart unless-stopped
    - Define named volumes for all three services

    `docker-compose.override.yml` (local dev convenience):
    ```yaml
    services:
      ib-gateway:
        ports:
          - "127.0.0.1:5900:5900"  # VNC for IB Gateway debugging
    ```
    Note: Only expose VNC in override (dev only), not in base compose.

    **Application entrypoint (`src/trading/app.py`):**

    Create an async application class `TradingApp` with:
    - `__init__(self, settings: Settings)` storing settings
    - `async startup(self)` method that:
      1. Configures structlog (JSON or console based on settings.logging.format)
      2. Logs a prominent startup banner showing: trading mode (PAPER/LIVE in caps), IB host:port, database URL (masked password), Redis URL
      3. If mode is "live", log a WARNING-level message: "LIVE TRADING MODE ACTIVE"
      4. If mode is "paper", log an INFO-level message: "Paper trading mode (safe)"
    - `async shutdown(self)` method placeholder (will be filled in future plans)
    - A `main()` async function at module level that loads Settings, creates TradingApp, and calls startup

    Configure structlog in a `setup_logging(settings)` function:
    - If format is "json": use `structlog.dev.ConsoleRenderer` replaced with `structlog.processors.JSONRenderer`
    - If format is "console": use `structlog.dev.ConsoleRenderer` for human-readable output
    - Add standard processors: timestamp, log level, stack info for exceptions
