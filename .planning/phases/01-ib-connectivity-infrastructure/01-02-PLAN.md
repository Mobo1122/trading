  <action>
    **Database engine (`src/trading/db/engine.py`):**

    Create `create_db_engine(database_url: str, pool_size: int = 10, pool_overflow: int = 5)` that returns an `AsyncEngine` using `create_async_engine` with:
    - `pool_pre_ping=True` (verify connections before use)
    - `echo=False`
    - Configurable `pool_size` and `max_overflow`

    Create `create_session_factory(engine: AsyncEngine)` that returns an `async_sessionmaker` with `expire_on_commit=False`.

    **Session manager (`src/trading/db/session.py`):**

    Create an async context manager `get_session(session_factory)` that yields an `AsyncSession`, commits on success, rollbacks on exception. Use `asynccontextmanager` decorator.

    **ORM Models (`src/trading/db/models.py`):**

    Create a `Base` class using `DeclarativeBase`.

    Define `OrderState` enum (str, enum.Enum) with values: `CREATED`, `API_PENDING`, `PENDING_SUBMIT`, `PRE_SUBMITTED`, `SUBMITTED`, `PENDING_CANCEL`, `FILLED`, `CANCELLED`, `ERROR`.

    Define `Order` model:
    - `__tablename__ = "orders"`
    - `id: Mapped[str]` (UUID as string, primary key, use `uuid4` default via Python)
    - `symbol: Mapped[str]`
    - `sec_type: Mapped[str]` (STK, OPT, FUT, etc.)
    - `action: Mapped[str]` (BUY, SELL)
    - `quantity: Mapped[float]`
    - `order_type: Mapped[str]` (MKT, LMT, STP)
    - `limit_price: Mapped[Optional[float]]`
    - `stop_price: Mapped[Optional[float]]`
    - `current_state: Mapped[str]` (OrderState value, default CREATED)
    - `ib_order_id: Mapped[Optional[int]]`
    - `ib_perm_id: Mapped[Optional[int]]`
    - `fill_price: Mapped[Optional[float]]`
    - `filled_quantity: Mapped[Optional[float]]`
    - `created_at: Mapped[datetime]` (server_default=func.now(), timezone-aware)
    - `updated_at: Mapped[datetime]` (onupdate=func.now(), timezone-aware)
    - Relationship to `OrderStateTransition` via `order_id`

    Define `OrderStateTransition` model:
    - `__tablename__ = "order_state_transitions"`
    - `id: Mapped[int]` (autoincrement primary key -- needed alongside timestamp for hypertable)
    - `timestamp: Mapped[datetime]` (DateTime(timezone=True), server_default=func.now(), index=True)
    - `order_id: Mapped[str]` (ForeignKey to orders.id)
    - `from_state: Mapped[Optional[str]]` (nullable for initial state)
    - `to_state: Mapped[str]`
    - `event: Mapped[str]` (the transition event name, e.g. "submit", "fill")
    - `details: Mapped[Optional[str]]` (JSON string for extra context)

    Note on hypertable: Do NOT use the `sqlalchemy-timescaledb` dialect. We will create the hypertable via raw SQL in the Alembic migration. This avoids a fragile dependency.

    Export `Base`, `Order`, `OrderState`, `OrderStateTransition` from `db/__init__.py`.

    **Alembic setup:**

    Initialize with `uv run alembic init --template async alembic` (async template is critical -- see research Pitfall 6).

    Edit `alembic.ini`:
    - Set `sqlalchemy.url` to a placeholder (will be overridden by env.py)

    Edit `alembic/env.py`:
    - Import `Settings` from `trading.config` and load database URL from config
    - Set `target_metadata = Base.metadata` from `trading.db.models`
    - Override `sqlalchemy.url` in the config from Settings
    - Use `async_engine_from_config` for both online and offline migrations

    Create first migration `alembic/versions/001_initial_schema.py` (manually, NOT auto-generated, to control hypertable creation):
    - Create `orders` table with all columns
    - Create `order_state_transitions` table with all columns
    - After creating `order_state_transitions`, execute raw SQL: `SELECT create_hypertable('order_state_transitions', 'timestamp')` -- this MUST be in the same migration as table creation (research Pitfall 5)
    - Add indexes: `order_state_transitions` on `(order_id, timestamp)`

    Use the revision naming convention: `001_initial_schema` (not auto-generated hash).
