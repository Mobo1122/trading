    - `filled` (final)

    Transitions:
    - `submit`: created -> api_pending
    - `sent`: api_pending -> pending_submit
    - `pre_submit`: pending_submit -> pre_submitted

    - `request_cancel`: pending_submit -> pending_cancel | pre_submitted -> pending_cancel | submitted -> pending_cancel
    - `fill`: submitted -> filled | pre_submitted -> filled
    - `partial_fill`: submitted -> submitted (self-transition for partial fills)
    - `cancel`: pending_cancel -> cancelled | submitted -> cancelled
    - `api_cancel`: pending_cancel -> cancelled | api_pending -> cancelled
    - `reject`: api_pending -> error | pending_submit -> error | pre_submitted -> error | submitted -> error

    Add an `on_enter_state` callback that stores the transition details (source state, target state, event name) on the instance for the tracker to read. Use a list attribute `self._pending_transitions` that the tracker consumes.

    Add `order_id: str` as a model attribute (set during init) so transitions know which order they belong to.
