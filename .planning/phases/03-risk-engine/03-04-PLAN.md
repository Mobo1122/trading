<task type="auto">
  <name>Task 2: Circuit breaker with dual-storage state management</name>
  <files>src/trading/risk/circuit_breaker.py</files>
  <action>
Create `src/trading/risk/circuit_breaker.py` with a `CircuitBreaker` class.

**`CircuitBreaker`** -- initialized with `redis` (redis.asyncio client), `repository` (RiskRepository), `mode` (str: paper/live), `limits` (LossLimits config):

**Redis key**: `risk:circuit_breaker:{mode}` -- hash with fields:
- daily_realized_loss, weekly_realized_loss (float as string)
- daily_halted, weekly_halted ("true"/"false")
- halted_at (ISO timestamp or empty)
- last_reset_daily, last_reset_weekly (ISO timestamp)

**`async check(self) -> RiskDecision | None`**
- Check if any halt is active via Redis HGETALL
- If `daily_halted == "true"`, return RiskDecision(approved=False, violated_rule=DAILY_LOSS_LIMIT, details with halted_at timestamp)
- If `weekly_halted == "true"`, return RiskDecision(approved=False, violated_rule=WEEKLY_LOSS_LIMIT, details with halted_at timestamp)
- Also check emergency_halt from limits config -> return EMERGENCY_HALT if active
- Return None if no halt active

**`async record_realized_loss(self, loss_amount: float) -> None`**
- Use Redis HINCRBYFLOAT for atomic increment of daily_realized_loss and weekly_realized_loss (per RESEARCH.md Pitfall 4)
- After increment, check if new totals exceed limits
- If daily exceeded: call `_activate_halt("daily")`
- If weekly exceeded: call `_activate_halt("weekly")`
- `loss_amount` should be positive (represents dollars lost)

**`async _activate_halt(self, halt_type: str) -> None`**
- Set `{halt_type}_halted` to "true" in Redis
- Set `halted_at` to current UTC ISO timestamp in Redis
- Get current loss values from Redis
- Persist to Postgres via repository.save_circuit_breaker_state()
- Log at WARNING level: "Circuit breaker activated" with halt_type, mode, loss amounts

**`async load_from_db(self) -> None`** (called on startup)
- Load circuit breaker state from Postgres via repository.load_circuit_breaker_state()
- For each record: if halted==True, write halt state into Redis
- Also write current loss accumulators from DB to Redis
- This ensures halt state survives Redis restarts

**`async check_and_reset(self) -> None`** (called periodically or on each check)
- Use `zoneinfo.ZoneInfo("America/New_York")` for ET timezone
- Daily reset: if current ET time >= 9:30am AND last_reset_daily is not today, reset daily_realized_loss to 0, set daily_halted to false, update last_reset_daily
- Weekly reset: if it is Monday AND current ET time >= 9:30am AND last_reset_weekly is not this Monday, reset weekly_realized_loss to 0, set weekly_halted to false, update last_reset_weekly
- Per RESEARCH.md Pitfall 5: daily reset does NOT clear weekly halt. Weekly reset does NOT clear daily halt.
- After clearing, persist the cleared state to Postgres

Use structlog with `bind(component="circuit_breaker")`. All datetime operations use timezone-aware `datetime.now(timezone.utc)`.
