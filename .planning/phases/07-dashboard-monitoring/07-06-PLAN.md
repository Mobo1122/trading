  1. Add scipy and numpy to `pyproject.toml` dependencies:

  2. Create `src/trading/dashboard/scenario_engine.py`:
     - `black_scholes_price(S, K, T, r, sigma, option_type) -> float`:
       - S: underlying price, K: strike, T: time to expiration (years), r: risk-free rate, sigma: IV, option_type: "C" or "P".
       - If T <= 0: return intrinsic value (max(S-K, 0) for call, max(K-S, 0) for put).
       - Compute d1, d2 using standard Black-Scholes formula.
       - Use `scipy.stats.norm.cdf` for cumulative distribution.
       - Return call or put price.

     - `scenario_pnl(positions, underlying_change_pct, iv_change_pct, days_forward, risk_free_rate=0.05) -> dict`:
       - `positions`: list of dicts, each with: underlying_price, strike, dte (days to expiration), implied_vol, quantity, multiplier (default 100), right ("C" or "P"), symbol.
       - For each position:
         - Compute current theoretical value via black_scholes_price.
         - Compute scenario values: S_new = S * (1 + change/100), sigma_new = sigma * (1 + iv_change/100), T_new = max((dte - days_forward) / 365, 0).
         - Track per-position P&L: (scenario_price - current_price) * quantity * multiplier.
       - Return dict with: current_value, scenario_value, pnl, pnl_percent, per_position (list of dicts with symbol, current_value, scenario_value, pnl for each position), skipped (list of symbols skipped due to incomplete data).
       - Round all values to 2 decimal places.
       - Handle edge cases: empty positions list returns all zeros, zero current_value returns 0 pnl_percent.

  3. Create `src/trading/dashboard/routes/scenarios.py` with APIRouter (prefix="/api/scenarios", tags=["scenarios"]):

     - `POST /api/scenarios`: Runs scenario analysis on current portfolio.
       - Request body: `ScenarioRequest` (underlying_change_pct, iv_change_pct, days_forward, risk_free_rate).
       - Fetch current positions: query DB for filled orders to derive open positions. For each position, overlay real-time data from Redis (latest quote price, latest Greeks for IV and underlying price).
       - **Contract detail resolution for single-leg orders (IMPORTANT):**
         For single-leg option orders, `combo_legs` is NULL and the `Order` table does not store strike/expiry/right directly. To get these details:
         a. First, try Redis contract cache: look up `contractcache:{symbol}` or iterate `mktdata:latest:greeks:{con_id}` keys for matching symbol to extract strike, expiry, right from cached contract data.
         b. If not found in Redis, try parsing the option symbol itself if it follows OCC format (e.g., "SPY240119C00450000" encodes expiry=2024-01-19, right=C, strike=450.00).
         c. If neither approach yields contract details, skip that position and add its symbol to a "skipped" list in the response. Log a warning.
         This ensures scenario analysis works for the common case (contract data cached from previous market data streaming) and gracefully degrades when cache is cold.
       - Build the positions list expected by scenario_pnl: for each open option position, need underlying_price (from Redis quote), strike (from contract detail resolution), dte (computed from expiration date - today), implied_vol (from Redis Greeks), quantity, right.
       - Call `scenario_pnl()` and return `ScenarioResponse`.
       - Use `asyncio.to_thread()` for the scenario_pnl calculation if position count is large (>50), to avoid blocking the event loop. For small counts, call directly.
       - Get Redis from `request.app.state.redis`, session factory from `request.app.state.session_factory`.

  4. Update `src/trading/dashboard/server.py` to include scenarios router:
     - `app.include_router(scenarios_router)`
