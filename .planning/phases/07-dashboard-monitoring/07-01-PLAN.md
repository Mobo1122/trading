<objective>
Build the FastAPI WebSocket server that bridges Redis pub/sub channels to browser clients, providing the real-time data backbone for the dashboard. Also add a DashboardPublisher that writes health/position data from TradingApp to Redis so the dashboard server can consume it.

Purpose: All dashboard features depend on this server for both WebSocket streaming (positions, Greeks, health) and REST endpoints (trade history, scenario analysis). This is the data bridge between the existing trading system and the browser UI. The publisher ensures the Redis keys the dashboard reads (ib_status, heartbeat, pipeline_status, positions) are actually populated.

Output: Complete FastAPI dashboard server package with WebSocket connection management, Redis-to-WebSocket bridge, Pydantic response models, dashboard config, and a DashboardPublisher wired into TradingApp lifecycle.
</objective>

  1. Create `src/trading/dashboard/ws/__init__.py` (empty).

  2. Create `src/trading/dashboard/ws/manager.py` with `ChannelManager` class:
     - `_subscriptions: dict[str, set[WebSocket]]` -- channel name to set of WebSocket connections
     - `_ws_channels: dict[WebSocket, set[str]]` -- reverse mapping for cleanup
     - `async subscribe(ws, channel)`: Add ws to channel set and reverse map.
     - `async unsubscribe(ws, channel)`: Remove ws from channel set. Clean up empty sets.
     - `async unsubscribe_all(ws)`: Remove ws from all channels (for disconnect cleanup).
     - `async broadcast(channel, message: str)`: Send message text to all subscribers of channel. Catch exceptions per-send, collect dead connections, call unsubscribe_all for each dead ws.
     - `@property active_connections -> int`: Total unique WebSocket connections across all channels.
     Use structlog with component="channel_manager".

  3. Create `src/trading/dashboard/ws/bridge.py` with `RedisBridge` class:
     - Constructor takes `redis: Redis`, `channel_manager: ChannelManager`, `throttle_ms: int = 500`.
     - `CHANNELS` class variable: list of Redis channel patterns to subscribe to:
       `["mktdata:quote:*", "mktdata:greeks:*", "mktdata:stale", "dashboard:positions", "dashboard:health"]`
     - `async listen()`: Subscribe to channels via `psubscribe`, iterate messages. For each pmessage, map the Redis channel name to a dashboard topic name, JSON-wrap it as `{"type": "update", "channel": topic, "data": parsed_data}`, and broadcast via channel_manager. Handle CancelledError for clean shutdown (punsubscribe + close pubsub).
     - `_map_channel(redis_channel: str) -> str | None`: Map Redis channel names to dashboard topic names:
       - `mktdata:quote:{symbol}` -> `quotes:{symbol}`
       - `mktdata:greeks:{symbol}:{con_id}` -> `greeks:{symbol}:{con_id}`
       - `mktdata:stale` -> `staleness`
       - `dashboard:positions` -> `positions`
       - `dashboard:health` -> `health`
       - Unknown channels -> None (skip)
     - Implement update throttling: batch incoming messages per channel, flush every `throttle_ms` milliseconds. Use a dict buffer `_pending: dict[str, str]` that gets flushed on a timer. This prevents broadcasting every single tick (can be hundreds per second).
     Use structlog with component="redis_bridge".

  4. Create `src/trading/dashboard/routes/__init__.py` (empty, routes added by later plans).

  5. Create `src/trading/dashboard/server.py`:
     - `create_app(settings: Settings | None = None) -> FastAPI`: App factory function.
       - If settings is None, load from `Settings()`.
       - Configure CORS middleware with `settings.dashboard.cors_origins`, allow methods=["*"], allow headers=["*"].
       - Use `@asynccontextmanager async def lifespan(app)` pattern:
         - Startup: Create Redis client via `create_redis_client(settings.redis.url)`. Create DB engine and session factory via `create_db_engine` / `create_session_factory`. Create ChannelManager. Create RedisBridge. Start bridge.listen() as asyncio.create_task. Store all on `app.state` (app.state.redis, app.state.session_factory, app.state.channel_manager, app.state.bridge_task).
         - Yield.
         - Shutdown: Cancel bridge task. Close Redis. Dispose DB engine.
       - Add WebSocket endpoint at `/ws`:
         - Accept connection.
         - Send initial snapshot: `{"type": "snapshot", "data": {}}` (actual snapshot data populated by later plans via Redis HGET).
         - Loop: receive JSON messages. Handle `type: "subscribe"` (subscribe ws to channel via channel_manager, send channel-specific snapshot from Redis HGET), `type: "unsubscribe"`, `type: "ping"` (respond with `{"type": "pong"}`).
         - On WebSocketDisconnect: unsubscribe_all.
       - Create a `get_db_session` FastAPI dependency that yields an async session from `app.state.session_factory` (for use by REST route handlers in later plans). Use the same pattern as `trading.db.session.get_session` but adapted as a FastAPI Depends generator.
       - Add a health check GET endpoint at `/api/health` returning `{"status": "ok"}`.
     - `def run_server(settings: Settings | None = None)`: Convenience function that creates the app and runs it with `uvicorn.run(app, host=settings.dashboard.host, port=settings.dashboard.port)`.

  6. Create `src/trading/dashboard/publisher.py` with `DashboardPublisher` class:
     - Constructor takes `redis_client: Any`, `ib: Any`, `health_monitor: Any | None = None`, `interval: int = 5`.
     - `async start()`: Start the background publish loop as an asyncio.create_task. Store the task handle.
     - `async stop()`: Cancel the background task. Clean up.
     - `async _publish_loop()`: Runs forever in a try/except CancelledError loop:
       - Every `interval` seconds:
         a. **IB status**: Check `ib.isConnected()` (or equivalent). Write `redis.set("dashboard:ib_status", "connected" if connected else "disconnected")`. Also `redis.publish("dashboard:health", json_blob)` for real-time WebSocket push.
         b. **Heartbeat**: Write `redis.set("dashboard:heartbeat", datetime.now(timezone.utc).isoformat())`.
         c. **Pipeline status**: Check the health_monitor or a status flag. Write `redis.set("dashboard:pipeline_status", status_str)`. Default to "idle".
         d. **Positions**: If IB is connected, call `ib.positions()` or `ib.portfolio()` to get current positions. Serialize as JSON. Write `redis.set("dashboard:positions", json_blob)`. Also `redis.publish("dashboard:positions", json_blob)` for real-time push.
       - All operations wrapped in try/except per-item so one failure doesn't stop the loop. Log warnings on errors (non-fatal, matching project convention).
     - Use structlog with component="dashboard_publisher".

  7. Wire DashboardPublisher into `src/trading/app.py`:

     - In `connect_ib()` method (after IB is connected), call `await self.dashboard_publisher.start()`. This is non-critical -- wrap in try/except with warning (matching Phase 2-6 bootstrap pattern).
     - In `shutdown()` method, call `await self.dashboard_publisher.stop()` before IB disconnect (matching existing shutdown order convention).
